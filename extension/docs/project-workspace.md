# Project and fabrication workspace (0.10.0)

Click **Project** in a schematic or PCB viewer, or open a supported settings/fabrication file directly. On GitHub the browser extension previews these files inline. In VS Code they open in a read-only custom editor; Project opens a separate project-review panel.

The project browser follows saved directories and files. It lists `.kicad_pro`, `.kicad_prl`, `.kicad_dru`, `.kicad_wks`, symbol/footprint library tables, schematics, boards, common Gerber extensions and Excellon drills. A PCB exposes saved setup and physical stackup, then **Open drawing** opens the existing interactive layout viewer. Schematics open their dedicated viewer. The browser project view embeds that drawing; VS Code opens a native editor beside it. The original viewers retain pairing, cross highlighting and comments.

**All settings** exposes saved fields, including unknown fields, searchable by field/value/source path. Click a value to inspect it without editing. **Constraints & rules** groups design settings, net classes, ERC and saved setup. `.kicad_dru` rules are parsed and displayed, never executed. PCB geometry is omitted from the settings tree and remains in the drawing and source views. Missing values are not filled with guessed defaults. Source display is bounded to its first 1 MiB.

Choose a PCB and **View board setup** to see saved physical layers, thickness in mm, materials, dielectric constants, loss tangents and finish. Stackup comes from the PCB, not inferred from a project file. Repeated dielectric thickness entries are reported as sublayers instead of treating the first as total thickness. This is a view of saved KiCad 10 data and directory structure, not a complete clone of the native KiCad project manager or effective rule resolver.

**Gerbers & drills** is our own browser engine. Click fabrication files to overlay them; change visibility, color and opacity, focus one layer or restore all, fit, pan, zoom, inspect saved operations and measure distances. Clear-polarity operations erase only their own layer. Round Excellon holes are supported when units/format are declared. Macros and curved regions are omitted with diagnostics; transformations, step-repeat and drill slots are rejected. See [Gerber support](gerbers.md). Unsupported geometry must not be treated as a complete fabrication rendering. Compound regions and clear operations are not pickable; selection describes saved operations rather than final composited copper.

Discovery is capped at 1,000 supported files and warns about truncation; workspace discovery additionally caps at 5,000 files scanned. Files are at most 8 MiB each. Gerber overlays are limited to 16 layers, 24 MiB source and 200,000 saved operations. Linked local files are rejected before reading; GitHub symbolic-link entries are omitted from discovery. GitHub discovery pins reads to a commit SHA; VS Code reads current workspace bytes. Refresh structure after files change.

Verification used own schematic/board fixtures, synthetic project/stackup demonstrations clearly labeled in the preview, and Gerbers exported by installed KiCad **10.0.6** from the retained sensor board. Native exports used `--disable-aperture-macros`. The outline recovered 80–150 mm X and 65–115 mm Y plus its saved 0.1 mm stroke. Browser fixture transport is mocked; installed extension behavior on GitHub and native VS Code visual acceptance remain separate checks.
