# Security assessment — 27 October 2026

> Historical assessment of the pre-0.12.63 baseline. The subsequent security release incorporates these corrections; see [current deployment profiles](HARDENED-DEPLOYMENT.md) for additional enforced controls and remaining limitations.

## Decision

**Do not treat the current published builds as approved for high-security environments.** This assessment found and corrected concrete boundary defects in source. The installed Android 1.64 and published 0.12.62 packages predate these fixes. No patched release, store upload or phone installation was performed as part of this assessment.

This is a source review, automated static/dependency analysis and local adversarial regression exercise. It is **not** an independent penetration-test certification, an OWASP ASVS/MASVS certification, a guarantee of confidentiality, or proof of resistance to zero-days, compromised hosts, timing/CPU side channels or malicious privileged extensions. Severity below is contextual engineering triage, not a formally scored CVSS assessment.

## Scope and method

Baseline: `e798097` on `main`, plus the uncommitted corrective changes described here. Scope includes the shared browser renderer and import/report paths, Chromium/Firefox/Safari packaging, browser credential/message/transport boundaries, Android WebView/native/picker paths, VS Code webview/Git/provider boundaries, Python local viewer/legacy renderer/hosted GitHub service, native KiCad launcher, CI and release tooling.

Three independent workstreams reviewed browser, native Android/VS Code, and supply-chain/platform code, with integration review of their patches. All adversarial tests used owned synthetic projects, mock providers or loopback listeners. No attacks were sent to GitHub, GitLab, employer networks or colleagues' machines. No private hardware sources or production credentials were used. No source was uploaded to a cloud scanning service.

Guidance used: [OWASP ASVS](https://asvs.owasp.org/), [OWASP mobile WebView boundaries](https://mas.owasp.org/MASWE-0033/), [Android native bridge guidance](https://developer.android.com/privacy-and-security/risks/insecure-webview-native-bridges), and [VS Code Workspace Trust extension guidance](https://code.visualstudio.com/api/extension-guides/workspace-trust). These supplied review criteria; this assessment does not assert compliance with their complete checklists.

## Corrected findings

| ID / contextual severity | Finding and prerequisites | Correction and evidence |
| --- | --- | --- |
| KIVI-SEC-01 / Medium | A repository with a preconfigured executable `core.fsmonitor` could execute it during supposedly read-only Python Git inspection. Merely cloning ordinary repository contents does not install that setting. | All helper Git calls override fsmonitor and untracked-cache settings, disable optional locks, strip ambient `GIT_*` repository/config overrides, disable lazy fetching and reject transport helpers. Synthetic tests also prove `GIT_DIR`/`GIT_WORK_TREE` cannot redirect inspection and even a local transport is rejected. The partial-clone concern was identified by independent source review; no hostile partial-clone helper was executed. A real synthetic Git positive control executes a harmless marker hook; protected inspection returns files without executing it. `tests/test_git_security.py`. |
| KIVI-SEC-02 / Medium, conditional | A malicious selected Android document handler could return `file://` rather than a granted document URI. Existing picker paths delegated to ContentResolver/WebView without a scheme guard, potentially exercising the app's private-file authority. This was established by code-path review and URI-policy probes; private-file theft was not executed on a device. | Picker results/imports/exports accept bounded, hierarchical `content://` URIs with validated authorities only. Invalid exports clear pending state without attempting deletion of an attacker-chosen destination. WebView result arrays are also bounded. `NativeBridgePolicy.java`, `MainActivity.java`, `NativeBoundarySecurityTest.java`. |
| KIVI-SEC-03 / Medium | Conflict viewing could activate/query VS Code Git without Workspace Trust; trust could also change during asynchronous activation/provenance resolution. | Check trust before Git activation/metadata access and after awaited activation/provenance. Recheck active session before credential-bearing requests and credential storage. Synthetic tests reproduce pre-fix violations; no real account tokens used. |
| KIVI-SEC-04 / Medium | Already queued VS Code webview requests could survive closure; thousands of authenticated large messages could accumulate memory/work. Requires a compromised privileged webview caller rather than arbitrary website JavaScript. | Bound pending count and bytes, recheck disposal before executing queued work, and ignore responses for disposed views. Limit host queue to 128 requests and 8 MiB retained payload. Regression tests cover closure, count/byte admission, and trust revocation. |
| KIVI-SEC-05 / Medium | Browser content-script read requests could name a repository/PR/MR different from their sending page or come from a subframe. Synthetic privileged content-script calls demonstrated successful cross-repository reads. Ordinary website JS cannot directly invoke this isolated listener; remote token theft was not demonstrated. | Bind repository, PR/MR number and top-frame identity to the sender URL. Explicit viewer browsing retains its intended authority. GitHub and GitLab adversarial sender tests cover rejection. |
| KIVI-SEC-06 / Medium | Report CSV limits ran after allocation; sparse JSON could expand a small input to millions of cells. Opening malicious saved analysis could exhaust memory/CPU. | Enforce column/row/aggregate cell limits before growth, including a shared four-million-cell JSON table budget. Negative tests reproduce the previous allocation weakness. |
| KIVI-SEC-07 / Medium | Legacy native-render HTTP service allowed unauthenticated loopback jobs; lacked newer request framing/socket/queue controls and trusted an unsigned delivery ID for replay identity. Exposure depends on running that optional development service; loopback alone is insufficient against rebinding/local callers. | Require a >=24-character API key even on loopback; reject browser-origin API job requests and duplicate Authorization; reject ambiguous body framing/truncated bodies; cap connections at 32 with 10-second inactivity timeouts; bound webhook queue at 40; deduplicate signed bodies despite changed delivery IDs. Raw HTTP and synthetic signed-webhook tests. Legacy dedup lasts 24 hours, remains memory-only and this service remains unsuitable for high-security production. |
| KIVI-SEC-08 / Defense in depth | Local viewer lacked an HTTP CSP and socket admission budget despite existing Host/Origin/session/path controls. No standalone XSS exploit was demonstrated. | Same-origin connection policy, no inline scripts/forms/objects, bounded sockets/deadlines. Actual Edge loopback UI loads; controlled inline-script and external-fetch probes are blocked before external dispatch. Saved-project API still works. |
| KIVI-SEC-09 / Defense in depth | Unauthenticated fixed-host archive transport followed redirects; no attacker-controlled codeload redirect was demonstrated. | Archive downloads now use the existing redirect-rejecting opener so a service cannot be redirected into an internal destination. Transport regression uses synthetic archive bytes. |
| KIVI-SEC-10 / Medium supply-chain exposure | CI/release workflows consumed mutable Action major tags, including the publishing job. A moved upstream tag could change code granted the job's permissions. | Pin every external Action to the verified upstream full commit SHA; preserve release-version comments and add weekly Dependabot Action updates. No remote workflow was launched by the audit. |

## Remaining approval blockers and restrictions

1. **Rebuild and distribute patched artifacts.** Existing releases and the installed phone build do not contain these source fixes. A subsequent package must bind exact source revision, dependency inventory, checksums and signer; run installed extension/VS Code/phone acceptance before organizational approval.
2. **Isolate native KiCad execution.** The Python native-render CLI invokes KiCad with the account's OS privileges. Argument arrays do not sandbox KiCad or constrain every saved schematic/library/worksheet reference. Do not process untrusted designs through a privileged native-render service. Use a disposable nonprivileged container/VM with a read-only minimal root, no secrets, denied network, CPU/memory/process/disk limits and only the selected snapshot mounted, or use the browser-only viewer.
3. **Lock the build environment.** Action pins are corrected, but optional Python dependencies/build backends, npm transitive resolution, OS/SDK packages and toolchains still lack a single hash-locked reproducible bill of materials. Add reviewed lockfiles/SBOMs and independently verifiable signed attestations before controlled deployment. Co-generated SHA256SUMS alone is not publisher authenticity.
4. **Production Android signing and distribution.** Current channel uses a development-signed APK and an unsigned AAB. Approve an upload/release key, managed distribution, key custody and update process; inspect a final release manifest and verify debugging/backup/network/picker protections in that exact artifact. Device instrumentation and malicious-provider end-to-end tests remain necessary.
5. **Managed offline/private-design profile.** Use approved patched local-only packages in an OS-sandboxed, patched browser/device. Do not sign in or import bearer tokens; deny network egress at enterprise policy/firewall level, disable browser sync and unapproved extensions, restrict clipboard/screenshots/backups per policy, and store projects on approved encrypted storage. The tested loopback CSP blocks external fetches for that surface; it is not an enterprise-wide offline mode for all companion apps. Browser profile/VS Code/Android app compromise is outside the vault's protection boundary.
6. **Connected-review profile.** If approved separately, allowlist exact GitHub/GitLab origins, use short-lived least-privilege credentials and private-server TLS, restrict provider publication through server-side roles, protect logs/backups and explicitly approve screenshot uploads. GitHub `repo` and GitLab `api` OAuth scopes are broad. Client-only anti-spam policy is bypassable by a modified client and cannot replace provider/WAF controls.
7. **Hosted services.** Use the newer signed-webhook service behind a correctly configured TLS reverse proxy with absolute request/header/body deadlines and edge quotas. In-process inactivity deadlines and bounded threads do not provide complete slow-client/distributed DoS protection. The legacy native-render service is a development surface, not a production security profile.
8. **Coverage gaps.** No tracked iOS native implementation exists here; generated web staging is insufficient to audit an iOS bridge/signing chain. Installed Safari/macOS behavior, employer policy environments, live OAuth/SSO and provider scopes, physical tablet/foldable security and independent native WebView/browser fuzzing were not verified. No high-security claim extends to those gaps.

An organization must select a threat model and approve its exact patched build/deployment profile. The above restrictions are material requirements, not a guarantee that every attack vector has been eliminated.

## Integrated verification

- Full release gate: package preparation succeeded; 98 Python tests ran with zero failures and one Windows symlink-privilege skip; all 1,550 JavaScript tests passed.
- After adding the Android JVM test to normal discovery and the independent-review Git transport/environment hardening, the final full Python rerun executed **100 tests, zero failures, one symlink-privilege skip**. Log: `.vizdiff/security-python-integrated-final.log`.
