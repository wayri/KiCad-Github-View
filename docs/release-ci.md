# CI and prerelease publication

`.github/workflows/ci.yml` runs on branch pushes, ordinary pull requests and manual dispatch. It installs Python 3.11, Node 22 and the Python `github` extra, then runs `python scripts/release.py --output dist/release`. The script is the shared gate for tests and package assembly; CI does not duplicate or weaken those checks. Installing `.[github]` provides `cryptography` so credential-signing tests can run rather than skip for a missing optional dependency. The resulting verified assets and release evidence remain downloadable as a workflow artifact for 14 days.

`.github/workflows/release.yml` runs for pushed `v*` tags or a manual dispatch specifying an **existing** version tag. It rejects malformed names before checkout, checks out that exact tag with full history and no persisted credentials, runs the same script with `--tag`, and uploads its assets. The script checks manifest/tag versions. The publisher downloads the verified artifact, checks its SHA-256 list, confirms the remote tag still points at the tested commit, and publishes a **prerelease** with its release notes. A repeated run does not replace an existing release automatically; `gh release create` fails if it already exists.

Build jobs have `contents: read`. Only the separate publish job has `contents: write`, and its token is attached only to the GitHub CLI publication step. The publishing job never checks out or runs repository scripts. Ordinary pull requests cannot trigger publication; neither workflow uses `pull_request_target` or `workflow_run`. No PAT or store credentials are required for these GitHub Release workflows.

The release directory contains the Chrome ZIP, VSIX, optional hosted-viewer and GitHub App service ZIPs, `SHA256SUMS.txt`, `RELEASE-NOTES.md`, `release-manifest.json`, `INSTALL.md` and `THIRD-PARTY-NOTICES.md` produced by the release script. This publishes downloadable GitHub artifacts; it does **not** publish to Chrome Web Store, VS Code Marketplace or GitHub Marketplace. Repository access and account setup still apply. A local workflow inspection is not evidence that a hosted Actions run or publication succeeded.

The action major versions and their inputs were checked against the official [checkout](https://github.com/actions/checkout), [Python setup](https://github.com/actions/setup-python), [Node setup](https://github.com/actions/setup-node), [artifact upload](https://github.com/actions/upload-artifact) and [artifact download](https://github.com/actions/download-artifact) documentation. Workflows currently reference the official maintained major tags; update or pin those references through the repository's dependency review process when that policy is established.
