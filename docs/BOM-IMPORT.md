# Pocket KiView BoM interchange

`extension/bom-import.js` reads saved BoM data into the shared component manager. It never evaluates repository scripts, opens repository HTML as an executable document, or changes KiCad source files.

## Accepted files

- **KiCad and generic CSV/TSV:** a Reference, References, Ref, Refs, Designator or Designators column is required. Commas, semicolons and tabs, quoted cells, escaped quotes, embedded newlines and KiCad's trailing empty column are supported. Reference ranges such as `R1–R3` or `R1-R3` expand into individual components. Leading-zero ranges, mixed-prefix ranges, duplicate identities and quantity/reference discrepancies fail explicitly. Quantity means components per board; a separate build quantity does not generate duplicate components. Custom supplier and part fields remain text.
- **InteractiveHtmlBom JSON:** either the producer's `pcbdata` object or `{ "pcbdata": ..., "config": ... }`. The producer's `bom.both` stores reference/index pairs and `bom.fields` stores field arrays by footprint index. `config.fields` supplies their column names. Without those names positional values are retained as `Field 1`, etc.; the importer does not assume the first column is Value.
- **InteractiveHtmlBom standalone HTML:** literal `var pcbdata = {...}` and the producer's `JSON.parse(LZString.decompressFromBase64("..."))` representation are extracted as data. The application uses its own bounded base64 LZ wire-format decoder; none of the input scripts run. Arbitrary JavaScript expressions and other executable report layouts are rejected. Imported assembly geometry contains straight board edges and rotated footprint boxes, with reference and front/back associations. Exact arcs, text, pads, copper and net rendering are not reconstructed from iBOM. Unassigned excluded footprints, such as `REF**`, are omitted with a warning instead of assigned an invented designator.
- **WayriCAD BoM Studio JSON export:** the actual `bomstudio.exporters.export` table envelope (`project`, `variant`, `template`, `columns`, `rows`) is supported. Saved status, generation time and variant are retained. Engineering, Full audit and other custom tables work when they retain a component reference column. This represents the exported variant and scope. A workspace sidecar (`schema: 1`, `base`, `variants`) stores overrides rather than source components and requires an export to be opened here. Release ZIPs, XLSX and BoM Studio HTML reports are not imported by this reader; export a variant as JSON or CSV.

`Assembly`/`Population` DNP or DNI, explicit DNP flags and InBOM/exclusion columns are honored when present. iBOM `skipped` combines blacklist, DNP and variant filtering, so it is shown as excluded without claiming it is DNP. Saved prices and stock are observations from the file, not live distributor data.

## API and bounds

`KiCadBomImport.parse(text, path, options)` returns `{format, model: {kind: 'pcb', objects}, warnings, provenance, assembly, variant}`. Objects contain the shared design record's `metadata.properties`, `metadata.position`, `key`, `label`, `path`, plus `reference`, `properties`, `populated`, `excludeFromBom`, and `side` (`F`, `B`, or empty). Identity is stable within an unchanged imported file and is not substituted for a native KiCad UUID. `assembly` contains `{primitives, components, bounds}` when available. Coordinates are saved millimetres, with original board positions; back-side annotations do not modify those coordinates.

`candidate(path)` conservatively recognizes names containing `bom` or `ibom` with CSV, TSV, JSON or HTML extensions. Explicit import still accepts an arbitrary CSV/TSV filename. This avoids routing every simulation CSV into the BoM screen.

Import bounds: 16 MiB input and decompressed data; 50,000 components; 256 columns; 32,768 characters per scalar field; 100,000 drawing primitives. JSON is parsed as data, properties remain scalar strings and no imported markup is rendered by this reader.

## Compatibility evidence

The tests use the official [HP34401a OLED demo](https://openscopeproject.org/InteractiveHtmlBomDemo/html/hp34401a_oled.html), including its real compressed payload, and a JSON Full audit draft generated by the local BoM Studio producer from its `BOM_Demo` example. Source/producer hashes, retrieval provenance and fixture hashes are recorded in `extension/tests/fixtures/bom-import/provenance.json`. These examples verify interchange behavior, not purchasing readiness of the demo parts.

Format references: [iBOM producer](https://github.com/openscopeproject/InteractiveHtmlBom/blob/master/InteractiveHtmlBom/core/ibom.py), [KiCad geometry producer](https://github.com/openscopeproject/InteractiveHtmlBom/blob/master/InteractiveHtmlBom/ecad/kicad.py), [iBOM config](https://github.com/openscopeproject/InteractiveHtmlBom/blob/master/InteractiveHtmlBom/core/config.py), [LZ-string wire format and MIT license](https://github.com/pieroxy/lz-string). BoM Studio adapter evidence is `bom_studio_plugin/bomstudio/exporters.py` in the local kiWay checkout; the fixture records its hash.
