# Install and review (0.9.4)

The desktop VS Code extension is installed in the normal profile. The prepared Git demo is `.vizdiff/vscode-demo-project`: `pic_programmer.kicad_sch` references `pic_sockets.kicad_sch`, and `ebrake1.kicad_pcb` provides PCB inspection. Its empty `.kicad-review.json` is committed in that disposable repository. Drawing source bytes were copied unchanged.

In VS Code, reload the window if the old extension remains active. Expand **KiCad Review** in Explorer and select a drawing. If it opens as text, use **Reopen Editor With → KiCad Visual Review**. Use the sheet selector for subsheets and Parts/Nets for inspection. Review notes save to the project sidecar; stage and commit it through Source Control. The extension never commits automatically.

For Chrome, open `chrome://extensions`, enable Developer mode, choose **Load unpacked**, and select `D:\PROJECTS-DEV\Kicad-plugins-dev\nativegitvizdiffkicad\extension`. Reload an already-open GitHub file page. The upload ZIP is `.vizdiff/kicad-visual-review-extension-0.9.4.zip`; it is not published in Chrome Web Store. Installation in Chrome remains user-operated because no Chrome surface is connected to this session.

From the inline viewer's Review panel, open **GitHub sign-in and review file**. Configure your registered OAuth App client ID and use GitHub device sign-in, or enter your own token as a fallback, and connect/create `.kicad-review.json` in your checkout. Do not put the token into source files or chat. Chrome retains it only for the browser session.

Choose an Issue or Discussion destination (load a category for new Discussions), save a review note, then click **Publish to GitHub**. The local annotation retains its part/location/variant anchor, severity, tags, state and remote thread link. GitHub publication is explicit; changing local state does not close a remote issue. Source previews still support public repositories only. Discussion readback and native VS Code token publishing are not implemented.

Validation: 204 extension/VS Code JavaScript tests plus 3 SPIKE component tests pass, including note metadata, token isolation, issue/discussion requests, duplicate-post prevention, sidecar conflict detection and navigation. Native desktop custom-editor smoke remains unverified because the isolated VS Code renderer failed to launch. Browser controls were checked using actual renderers with mocked transport, and no live GitHub posts were made.

In Setup, choose independent UI/drawing themes and ruler units. Standard/custom review pages include orientation, title, revision, company, date and nine comments. Source bytes remain unchanged. Point and Area tools anchor review notes; area notes can save/download a PNG. Attach downloaded images manually in a GitHub composer; the publish API does not upload screenshots.

Repository-linked WRL/VRML and self-contained GLB models load in SPIKE 3D. Absolute paths, global KiCad libraries, external model dependencies and STEP are unsupported and reported. See extension/docs/auth.md for OAuth registration prerequisites.

Layer navigation (0.9.1): in Explorer -> Layers, search by saved layer name, focus one layer, choose dim/isolate, and fit its drawable geometry. All/None/Front/Back/Copper presets are reversible with Restore view; the first visibility state is retained across consecutive presets and focus operations. Clear focus keeps current visibility, while Restore view restores it. The board outline and drill holes remain context in isolate mode; inactive layers cannot be picked. [ and ] cycle focus, Shift+F fits it, and Escape restores visibility. These controls apply to 2D PCB review; schematic net focus and SPIKE 3D retain their existing controls. Layer preferences are session-only.

Ruler update (0.9.2): press M, click a start point, move the cursor for a live distance/angle/X/Y overlay, and click again to pin it. Choose geometry/grid/off snapping and grid spacing in millimetres. Geometry snapping uses only visible saved geometry, respects layer isolation, and prefers pad/pin centers and endpoints within eight screen pixels. Alt bypasses snap; Shift constrains horizontal/vertical. New measurement resets the ruler; Escape exits. Drawing measurements use the configured mm/mil display units and work in flipped 2D views. Board extents reports the axis-aligned bounding dimensions of all saved Edge.Cuts shapes, including detached panels and arcs, excluding stroke width; it does not validate a closed manufacturable outline. No board or schematic source is modified. Ruler snap/grid options are session-only; 3D measurement remains unavailable.


Schematic navigation and inspection (0.9.3): Explorer -> Sheets lists loaded schematic hierarchy, marks the active sheet, searches names/paths, opens subsheets and locates their saved sheet symbol in the parent. Selection outlines the complete source-bound object geometry. File views are shared for repeated sheet instances; instance-specific cross-sheet connectivity and buses are not resolved. Nets selects and highlights the active sheet network, with connected pins in the inspector.

Parts search accepts combined literal fields (`ref:R1 value:"10 k" -type:pad`, `net:VCC`, `footprint:QFP`, `sheet:power`) and simple custom property names. Enable All sheets for loaded-file searches. Net searches on files that have not yet rendered have no connectivity index; open that sheet first. No regular expressions are evaluated.

Both inspectors include expandable, filterable Saved KiCad settings separate from effective assembly overrides. These preserve original quoted/empty/duplicate fields and nested settings, including footprint pads/models and embedded symbol definitions for common and placed units. Inspection is bounded to 20,000 nodes/512 Ki characters per source tree and 300,000 nodes/16 Mi characters per project; omissions and truncated data are explicitly disclosed. Native KiCad editing dialogs and computed ERC/DRC properties are not implemented.


GitHub leaf-sheet previews discover parents in the selected file directory and ancestor directories (up to 8 levels, 24 candidates). Only matching ancestor projects and their referenced descendants are returned, within the existing 32-file/24 MiB preview budget. Discovery failures show a rendering note and retain the selected subtree. A parent in another sibling directory must be opened directly. VS Code loads the selected file and its descendants; open the root for the complete hierarchy. Worksheet numbering in file views is review traversal numbering rather than KiCad instance-specific numbering.


Paired review and comments (0.9.4): use Split schematic + PCB in the inline GitHub preview. Select an opposite-kind file from the same directory, or enter a repository-relative path. Both files stay on the same repository/revision. Both panes, single-pane focus, Stack panes, Fit panes and Pop out provide different workspace sizes. Pop out requests a maximized extension window. In VS Code, run KiCad Visual Review: Open Schematic and PCB Side by Side from the command palette or drawing context menu; select a same-directory counterpart. Only explicitly paired editors relay selections.

Cross-highlighting uses the saved schematic UUID / footprint path when available, then a unique exact reference. Ambiguous repeated references and conflicting saved identities are rejected. Net linking uses exact names on the active schematic sheet and PCB; hierarchical aliases are not inferred. Cameras remain independent. Part and net inspectors, variants and comments remain usable in both panes. Narrow windows keep the inspector and explorer mutually exclusive after resizing.

Comments have independent Open, Skipped, Resolved and Won't fix lifecycle states, plus per-user Read/Unread status. Editing a previously read note makes it unread again. Sort by creation age, latest update or severity; use Next unread to advance review. Created/updated timestamps persist as UTC and display in local time. Structured mentions become @login references in GitHub publication. Local state changes do not update or close an existing remote thread.

Add a Git-controlled `.kicad-review-policy.json` to the repository default branch to permit all users, contributors, collaborators or named reviewers. An optional allowlist admits invited reviewers alongside restricted modes. See [comment policy](../extension/docs/comment-policy.md) for the schema and enforcement limits. The extension checks the target default branch immediately before posting; these rules cannot restrict direct GitHub website comments.

Validation for 0.9.4: the JavaScript suites and packaging checks cover comment metadata, policy enforcement, trusted popup routing, paired selections and native editor pairing. Local browser QA used real renderers with mocked transport, including cross-highlight in both directions, read/skip/mention edits, pane focus, stacked layout and a 640 CSS-pixel workspace. Live Chrome popup, GitHub posting and native desktop editor UI are not verified in this session.
