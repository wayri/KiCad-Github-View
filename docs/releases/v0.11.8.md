# v0.11.8 — direct GitHub review posting

The schematic, PCB and comparison comment editors now let you choose **Issue** or **Discussion**, new or existing thread, title or thread number, and a category for new Discussions. **Post to GitHub** saves the draft and submits it directly using the connected account; confirmed posts retain their GitHub link. **Save draft** remains available without posting. Failed publication leaves an editable draft, with existing pending-publication protection retained for ambiguous responses.

Generated GitHub Markdown now has a review-comment section and design-context table with severity/state, destination type, component/net, position/area, repository, revision/file permalink, variant, saved identifiers, tags, mentions and UTC timestamps. **Preview GitHub Markdown** displays the body before posting. Captured PNG data is excluded; users can download and attach it manually. Legacy hidden annotation markers remain compatible with supported readback.

Authorized private repositories can receive Issue and Discussion publication. Private review policy reads are authenticated on GitHub's API; a missing policy is accepted only after a complete authenticated root listing confirms absence. Invalid identity, denied Contents access, incomplete listings and malformed/restrictive policies fail closed. Public policy verification remains anonymous. Private annotation readback and private PR comparisons remain unsupported.

Tests cover direct new/existing Issue/Discussion routing, category/number validation, previews without writes, confirmed-link persistence, failed-post drafts, provider isolation, Markdown escaping/round-trip and authorized/denied private publication. New screenshots show local fixture UI with mocked repository/category data. No live thread was created during verification.

Account connection still requires a configured publisher OAuth App client ID or the advanced token fallback. This build does not include a registered publisher ID; see the sign-in setup guide. Firefox remains an unsigned development package, and Safari remains a Mac conversion/signing payload with installed-browser acceptance outstanding.
