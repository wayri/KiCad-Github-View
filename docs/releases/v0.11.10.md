# v0.11.10 — configured GitHub sign-in

Browser packages now include the public Client ID of wayri's registered OAuth App. Users can choose repository access and click **Sign in with GitHub** without supplying an App ID in advanced settings. No client secret is included or required by Device Flow.

The encrypted authentication and cleanup protections introduced in v0.11.9 remain in place. Background restart requires sign-in again; local expiry is capped at eight hours. Sign-out and reset clear credentials, while GitHub authorization revocation remains a separate account action.

Automated checks cover the actual distributed Client ID, publisher fallback, custom developer configuration, scope validation and the existing authentication security suite. GitHub's live device-code endpoint accepted this Client ID and returned a valid verification URL and expiry; the temporary device secret was discarded without account approval. Live account approval and GitHub publication remain unverified. Device Flow must remain enabled in the publisher App settings.

Firefox remains an unsigned development package; Safari requires macOS conversion, signing and installed-browser verification. GitLab account connection and VS Code remote publication remain outside this change.
