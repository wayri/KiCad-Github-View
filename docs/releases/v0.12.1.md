# v0.12.1 — GitHub connection state

GitHub settings now refresh when returning from authorization, reopening the page or changing visibility. Changes to encrypted session records refresh other open settings windows, and the UI refreshes at the saved token expiry. Connected settings show **Reconnect GitHub** and enable Sign out; signed-out settings identify worker restarts, expired credentials and locked sessions where that evidence exists.

The toolbar badge shows a **green dot** for a locally connected GitHub credential, with an explicit connected/signed-out tooltip. Sign-out and reset clear it. Worker initialization removes a stale connected badge when the temporary encryption key has been lost. The indicator reflects the local credential, not a claim that GitHub has validated repository permissions or that an individual API request will succeed.

HTTP-hosted local preview settings now clearly identify themselves as a demo and disable sign-in controls. Real sign-in belongs in the installed extension's own settings page. This does not replace the installed-extension fix above.

Security behavior is unchanged: keys remain in background memory, copied ciphertext cannot unlock a new worker, and restart/reload requires reconnecting. Automated tests verify focus-return synchronization, storage changes, sign-out/reset badge transitions, restart/expiry diagnostics and unchanged vault protections. A live browser authorization failure still needs the actual status message to distinguish authorization, transport, scope and worker-lifecycle failures.

Device-code polling now runs in the privileged background until approval, cancellation or code expiry, even when settings-tab timers are throttled. Settings include **Test repository access**, a read-only API check that reports the verified account and whether the requested private repository is readable. Neither the badge nor stored-token status substitutes for this API verification.
