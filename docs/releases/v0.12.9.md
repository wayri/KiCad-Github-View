## More drawing space and usable panels

Properties, Comments and the explorer have Tall / Wide controls and height resizing. Resize handles support keyboard arrows and Home/End without changing drawing zoom. A local 1707 × 960 renderer check increased the Comments panel from 343 to 531 pixels of reading height while preserving 86.0% unobscured drawing area within the viewer.

Short panes retain a visible compact panel header, with hidden body controls removed from keyboard/accessibility navigation. Expand opens full-height content for reading or editing; Restore returns to the drawing-area budget. Drafts survive expansion, closing and panel switching. A local 600 × 500 check retained 82.3% drawing area with the compact header visible; Expand provided 434 pixels of reading height and deliberately reduced drawing space. The toolbar scrolls horizontally without an extra scrollbar row. These are actual renderer checks with simulated repository transport, not guarantees for every installed host or full expanded sidebar.

## Safer recovery and GitLab comparisons

For newly recorded uncertain GitHub publications, enter the Issue or Discussion number and choose Recover published comment. Recovery performs read-only lookup and requires one exact annotation from the account that attempted publication. It restores the confirmed link and screenshot attachment receipt without submitting another post. Edited annotations, another author/account, ambiguous matches and older pending records without the author/content binding remain protected from retry. No live Issue/Discussion posting or image upload acceptance is claimed by this release.

If GitLab reports a limited or timed-out comparison, the viewer recovers changed drawings from both immutable commit trees. Complete discovery is required, with at most 1,000 tree entries per revision; incomplete discovery stops instead of creating false deletions. Unique byte-identical moves are recognized as renames. Edited or ambiguous moves appear as added/removed, with an explanation. Provider and authorized self-hosted worker tests verify request and credential isolation; installed GitLab acceptance remains pending.

## Whole-repository GitHub Actions review

Omit `file` from the composite Action to review every changed schematic and PCB. Use `merge-base: 'true'` for PR semantics and `output-directory` for the indexed report directory. The installed command is `kicad-vizdiff review --base BASE --head HEAD --merge-base --output kicad-review`; copying the legacy CI script is unnecessary. Artifact output remains available after drawing failures, and the job still reports failure.

Native review materializes each commit once and shares those snapshots across drawings. Per-drawing SVG exports remain separate. Native checks verify two snapshot copies, cleanup, unchanged tracked sources and report equivalence to independent single-file exports, ignoring only KiCad's generated SVG title timestamp.

Hosted KiCad 10 [whole-repository review](https://github.com/wayri/KiCad-Github-View/actions/runs/37230648164) generated three revision-bound reports, including six PCB views and a two-sheet root schematic. The subsequent [shared-snapshot validation](https://github.com/wayri/KiCad-Github-View/actions/runs/37231347413) passed native fidelity checks and report upload. These runs use the project's original synthetic fixtures; they do not establish electrical correctness or every hardware project's fidelity.

## Verification and remaining limits

Local gates passed 557 JavaScript tests and 64 Python tests with one skip, followed by all browser, VSIX, application, guide and STEP-source package builds. Hosted package CI passed on the implementation commit. This release retains the secure STEP preview and corresponding-source companion introduced in v0.12.8.

This is a prerelease. Installed private-host/browser workflows, native VS Code 3D visual acceptance, Firefox signing and Safari conversion/signing/runtime acceptance remain unverified. Absent model libraries still require repository assets or mappings. Source designs remain read-only; no routing or schematic editing is enabled. See `INSTALL.md`, `COMMENTS.md`, `GIT-HOSTS.md` and the README for setup, renderer limits and acknowledgements.
