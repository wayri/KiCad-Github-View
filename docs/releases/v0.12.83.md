# Pocket KiView 0.12.83 / Android 1.86 — preview

Browser and VS Code packages use **0.12.83**. Android uses **1.86**, version code
**89**. GitHub preview packages, store submission, store approval and device
acceptance are separate states.

## Large-board loading and mechanical drawings

- Removed a repeated whole-board format lookup from per-object PCB rendering.
  On the connected Samsung phone, the retained public 44 MB BerkeleyLab Marble
  board previously hit the two-minute preparation timeout; corrected runs loaded
  in about 14.6–15.4 seconds. These are observations on one device, not a general
  performance guarantee.
- Draftsman strips routing copper before preparing mechanical 3D geometry,
  shares its scene between projections and avoids creating hidden copper meshes.
  The retained Marble source shrank from 44,059,775 to 12,250,752 bytes for this
  mechanical projection while retaining its 1,006 footprints and 5,272 pads.
  Footprint/mounting drills remain; omitted routing-via holes are disclosed.
- Mobile Draftsman keeps the drawing full-screen with compact tool/property
  panels. PDF, SVG and editable JSON exports use Android's document save picker,
  with explicit type, size, structure and project-generation checks.

## Fast PI contact selection and overlays

- Fixed rotated footprint pad/drill coordinate handling to agree with the native
  PCB coordinate convention and the layout renderer.
- Searchable Source and Load suggestions show component reference, pin, layer and
  exact saved coordinates. Contacts can be cleared or repicked independently.
  Ambiguous/off-copper board touches offer choices instead of silently snapping.
- The contact chooser adapts between narrow bottom sheets and wider panels,
  retains state during resizing/rotation and avoids opening the phone keyboard
  before the user chooses to search.
- Smooth fields interpolate accepted DC samples with a blue/cyan/yellow/red
  palette. Saved copper, drill voids and solved-cell support clip the result;
  unsupported masking is reported and falls back to optional mesh diagnostics.
  Camera changes reuse cached field textures. Current, density and loss fields
  are interpolated mean incident-edge values, not an additional field solve.
- Small selected nets no longer exhaust input budgets merely because unrelated
  board geometry is large. Mesh, convergence and selected-geometry budgets remain
  bounded. Unsupported selected slots, offset drilled pads and other omitted
  electrical geometry remain explicit errors.

## Android local and repository workflows

The isolated in-app repository browser is separate from the trusted viewer.
Website-session loading and existing-Issue replies/readback use the explicitly
opened repository session without requiring broad repository OAuth access. This
does not bypass organization, browser, network or download policies. Provider
sign-in, device and organization acceptance remain environment-dependent.

Drive/OneDrive/local imports can use portable local review JSON files. Ordinary
comment refresh uses an inline status instead of a repeated global loading popup.

## DRC/ERC reports

Imported KiCad DRC/ERC reports can be discovered and reviewed in the viewer,
filtered by severity and shown as drawing markers with full item details and
location navigation. This reads saved reports; it does not run KiCad's rule
engine in the browser. Reports and locations must match the loaded design.
The illustrated report walkthrough identifies its synthetic QA data explicitly.

## Verification and limits

The prior full-Marble phone run passed 26 checks covering loading, Draftsman
generation/automatic dimensions, native contact taps, accepted DC results and
overlays. With explicit 0.1 A test loads, two selected nets solved in about
1.6–1.9 seconds including worker transfer; the cross-layer case contained 11 via
transition edges. One case required a 0.05 mm mesh. These are fixed-temperature,
single-net screening approximations; return impedance, AC and thermal feedback
are excluded. Mesh refinement remains necessary before relying on extrema.

The final added contact-chooser, smooth-field and save-picker phone run was
interrupted before completion. No final device acceptance is claimed for those
additions. Physical tablet/foldable acceptance and an installed Firefox session
are unverified. The retained Marble corpus lacks its external 3D model files;
the mechanical test does not establish full real-model coverage.

The release manifest records the final automated gates and exact source/package
audit. No private organization sources or screenshots are included. The Altium
experiment remains excluded. Firefox ZIPs are unsigned development packages;
Android APKs are non-debuggable, development-signed previews, and AABs are unsigned
and not Play-ready. No new store approval is implied.
