# v0.12.6 - Review readback and larger drawing views

GitHub annotation refresh uses the connected account for authorized private Issue/PR reads. A selected thread reads its body and up to 500 comments; an unselected scan reads 200 recent Issue/PR bodies. Existing Discussions support authenticated readback from marked bodies, comments and replies, bounded to 500 source records and 20 requests. Markers must match the exact drawing scope. URLs are canonical; author and posting/editing times come from GitHub responses. Account changes abort the read.

Reply creates a fresh anchored draft for the existing thread. Posting is explicit; confirmed posts select their thread for refresh. Reviewers can append their own posts and refresh them, without automatic state synchronization or design editing. Ordinary messages remain on GitHub. Discussion replies append to the conversation. Private PR revision comparison remains unavailable.

Panels target 86% unobscured drawing area per viewer frame. When several panels become too short, toolbar controls switch the active panel. Split review uses a compact header, thin separators and narrow icon toolbars. Local browser checks at 1707 x 960 measured 86.0% with Properties and Comments open and 80.6% across split schematic/PCB with a panel in each pane. Window size, popovers and the surrounding website affect area.

Verification uses network fixtures and actual local browser rendering. No live private repository, Issue, Discussion, reply or attachment was used. Installed-browser and live-provider acceptance remain necessary. Firefox packages are unsigned development builds; Safari requires macOS conversion/signing.
