# v0.12.0 — GitLab accounts and larger engineering views

Marble's legacy `Sheet file` and `Sheet name` properties now resolve alongside modern KiCad names. A read-only test of the public wayri/Marble project loaded all 25 unique schematic files (22.8 MB), including reused sheets, with four concurrent reads. Discovery is bounded to 128 drawing files and the existing project byte budget. The sheet browser has a larger tree, source links, and Back/Forward/Up/Root navigation. Reused files still share a file view; instance-specific connectivity is not resolved.

Project previews fill the available height and offer Focus drawing, Close preview and Hide/Show project files. Narrow drawing panes use overlay sidebars; Focus view or Ctrl+Shift+F hides review controls, with Escape restoring them. H, backtick and tilde highlight the pointed net; editing and routing remain unavailable. Layer focus supports dim or isolate modes. Ratsnest displays bounded **candidate** connections from saved copper, with warnings for zones/arcs and other unresolved connectivity; it is not native KiCad unrouted or DRC evidence.

Pan/zoom redraws coalesce per animation frame and offscreen geometry is culled with cached bounds. Workspace-scoped net snapshots avoid reparsing unchanged sheets: a local Marble check measured an unchanged refresh at 2 ms and opening its rendered Power sheet at 62 ms (one source rebuild); these are extraction timings, not browser frame-rate guarantees. SPIKE 3D retains its WebGL renderer; 2D remains Canvas2D. Repository model asset downloads use a bounded cache across 3D toggles, and safe Windows relative model paths are normalized. Up to 2,048 WRL/VRML/GLB instances share models within a 24 MiB asset budget; STEP import and installed global KiCad libraries remain unavailable. F/Home and +/- also fit or zoom the 3D view.

The browser extension now connects GitLab accounts for authorized private project/file/model reads and explicit remote reviews. GitLab credentials are encrypted per HTTPS server with non-extractable keys held only in background memory. Sign-out/reset purge credentials and invalidate pending login; reset also clears the server's public Application ID. Removing a self-hosted server unregisters previews and removes browser permission. Review notes are retained. Background restart requires reconnection, and sessions expire within eight hours or the provider's shorter expiry.

Options → **GitLab accounts and servers** supports expiring token connection and OAuth authorization code flow with PKCE and random state. OAuth needs a registered non-confidential application, `api` scope and the exact browser redirect URI. No publisher GitLab Application ID or client secret is bundled. Safari builds without the browser identity API must use token connection. Additional servers require an explicit permission grant for an exact HTTPS origin; URL-subpath installations are unsupported.

The shared viewer offers **Post to GitLab**, formatted Markdown preview, new/existing Issue destinations and discussions within existing issues. Saving remains local until the user explicitly publishes. Confirmed thread links are retained, while uncertain outcomes block automatic retry to prevent duplicate posts. The GitLab tab reads validated revision-bound markers from a selected issue description and at most 500 notes; ordinary comments are not converted into design annotations. Captured PNGs require manual upload through GitLab, and local state does not close issues or synchronize remote edits.

Repository policies are checked on the default branch before publication, including authenticated private access and fail-closed verification of missing/malformed policies. Contributors-only verification does not trust commit emails as account identity; use verified membership or an explicit allowlist. Credentials are never forwarded to GitHub or another GitLab server. Review anchors, receipts and import validation preserve exact provider/server context.

Updated installation, security, browser-port and illustrated GitLab guides accompany the release. Chromium, Firefox and Safari packages share the implementation. Firefox remains an unsigned development package; Safari remains a macOS conversion payload requiring signing and installed-browser verification. Merge-request file cards, self-hosted URL subpaths and VS Code remote posting remain unsupported. Automated mocks establish implementation contracts rather than live OAuth, account permissions, native installation or store acceptance.
