# KiCad Visual Review v0.12.31

This preview adds Android phone/tablet releases and publishes the shared viewer for Chromium browsers, Firefox, Safari conversion, VS Code and the web app.

- Android 1.25: public/private GitHub and GitLab projects, offline project copies and bookmarks, touch selection, resizable panels, BoM manager, compact controls and GitHub-only Value/custom-field edits exported in a copy.
- Shared viewer: compact toolbars, subtle theme-aware translucency, expandable floating PCB layer selector and BoM manager.
- VS Code: complete shared BoM assets; recognize both saved Sheetfile and Sheet file properties. Source load errors identify the affected file and give recovery guidance instead of an unrelated development-packaging instruction.

The Android APK uses development signing, not a production Play Store key. The AAB is unsigned. Firefox requires signing for normal distribution; Safari requires macOS conversion/signing. Marketplace/store publishing is separate. Native KiCad ERC/DRC is not implemented on Android. Fields are edited only in a revised copy; the original repository is not overwritten.

Verification: shared renderer and host tests, package inventory/hash checks, Android compilation/lint and local phone installation. Browser fixtures do not establish installed browser acceptance. The reported VS Code failure was traced to unresolved Git merge markers in the saved source. Parsers now report the conflict line explicitly and never choose a branch or modify the design.

## Visual Git conflict resolution in VS Code

Run **KiCad: Resolve Git Conflict Visually** on a saved schematic or PCB containing Git merge markers, or open that file in the KiCad viewer. Current and incoming candidates are rendered side by side with linked cameras and saved-object difference highlighting. Choose a whole side, then save a new copy or explicitly replace the original. Saving and staging require separate confirmation and a trusted workspace; Git staging uses VS Code's built-in Git API. No commit or push is automatic. Marker-free candidate syntax/root are validated before saving; this is not a native ERC/DRC result.

Unsaved edits and detected external file changes stop the save. Provider writes cannot provide an atomic filesystem compare-and-swap, so avoid concurrent external writes during resolution. The first version chooses one side across all conflicts; per-conflict visual assembly and project-wide merging are not implemented. Android and browser source viewing remain read-only for merge conflicts.
