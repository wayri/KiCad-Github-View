# v0.12.4 — More drawing space and independent review panels

Properties and Comments now open as separate collapsible, resizable flyouts, with independent scrolling. Comments has Add comment and View comments tabs; drafts survive tab switches and panel collapse. Property groups, comment filters, import/export and collaboration controls are collapsible. Resize edges support pointer dragging and keyboard arrows.

The compact toolbar includes active-sheet selection and Back/Forward/Up/Root navigation. View layout / View schematic uses a verified companion path, with a chooser when several drawings are available. Assembly variants, highlight controls, keyboard help and rendering diagnostics are in Review tools. Rendering notes remain indicated on that button. Focus view hides optional panels.

Panel height is budgeted against the drawing frame to target 82% unobscured drawing area. Local browser checks measured 82.0% with both review panels open and with Explorer also open at approximately 1706 × 960 CSS pixels. The original synthetic sensor fixture uses real renderers and mocked repository transport. This is not installed-extension acceptance or a guarantee for the entire GitHub page. Short frames retain readable panel controls and show a space warning when the target cannot be met.

Supported Chromium service workers now use a dedicated in-memory credential worker in an offscreen document. Encrypted session credentials can survive background service-worker idle suspension. Keys are not saved; browser restart, extension reload, key-worker loss, expiry, reset or sign-out can require authentication again. Unsupported browsers retain the background-memory fallback. Private MessageChannel transport connects the exact credential host and service worker. Installed Chrome lifecycle, real OAuth and uninstall behavior still need manual verification; encrypted storage does not protect against a compromised running browser profile or theft of a usable token.

This prerelease includes Chromium, Firefox development, Safari conversion-source and VS Code packages. Safari still requires macOS conversion/signing and native testing. No browser-store installation or live remote comment publication was performed as part of these checks.
