# v0.12.5 — Captured screenshots in GitHub reviews

Post to GitHub now uploads an area capture to GitHub's native repository attachment endpoint and embeds its confirmed image URL in new or existing Issues and Discussions. Confirmed URLs are saved with the local note and its remote thread link, and are included in the validated annotation marker for later readback. PNG bytes remain local and are not placed in Markdown metadata.

Uploads require repository write access and an OAuth or personal access token. GitHub App tokens and GitHub Enterprise Server are unsupported by this upload path. The extension checks the numeric repository identity, saved PNG dimensions and bounded decoded size. Upload responses are streamed within a 16 KiB limit; image URLs must match the exact GitHub attachment origin and UUID path. Authenticated upload requests reject redirects and never send website cookies. Chromium/Firefox/Safari manifests now authorize the fixed uploads.github.com host.

Failed uploads retain an editable draft without posting a text-only replacement. A confirmed upload receipt is reused if text publication fails definitively. Uncertain Issue/Discussion publication outcomes still prevent automatic retries. Signing out or changing accounts during upload stops subsequent publication. An interrupted upload or failed text post can leave an unreferenced GitHub asset; deleting local notes or signing out does not delete uploaded assets. GitHub controls private attachment access and retention.

The manual GitHub composer and GitLab capture workflow still require attaching the downloaded image yourself. There is no automatic two-way remote state synchronization. Automated tests use simulated network responses for all four destinations, permission and URL failures, authentication races and receipt recovery. No live Issue, Discussion or attachment was created for validation; installed-browser/live upload acceptance remains pending.
