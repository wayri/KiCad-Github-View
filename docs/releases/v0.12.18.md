# v0.12.18 — Faster preparation and visible loading

Large projects now prepare their initial drawing and connectivity in a bundled worker. A prominent centered spinner reports the current loading stage and elapsed time. File changes cancel stale preparation, and failures dismiss the overlay and retain an actionable error.

- Remove the duplicate project-model build and repeated metadata parsing.
- Index hierarchy connectivity instead of repeatedly scanning all links.
- Parse PCB settings without allocating an AST for omitted geometry; accept PCB sources within the existing 64 MiB drawing limit.
- Cache identical parsed settings within bounded page-local storage and avoid rebuilding unchanged settings panels.

On retained Marble sources, project model preparation fell from 3,857 to 1,016 ms in a single-run phase comparison. Full-board settings parsing was 27% faster with about 86% less heap allocation delta over five-run medians. These are preparation measurements, not whole-page speed guarantees. See [performance evidence and limitations](../PERFORMANCE.md).
