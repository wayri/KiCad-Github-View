# Hardened deployment profiles

## Managed apps and extensions

These controls ship in 0.12.63 / Android 1.65. The sideload APK is non-debuggable and retains the existing development signer for in-place updates; that signer is not a production identity. They preserve ordinary consumer defaults unless an administrator configures them; installing the update alone does not place a device in offline mode.

| Surface | Controls | Enforcement boundary |
| --- | --- | --- |
| Chromium / supported managed browsers | `NetworkEnabled: false`, `ProviderWritesEnabled: false` | Browser-managed extension storage; ordinary extension settings cannot override it |
| VS Code | `kicadVisualReview.networkAccess: false`, `kicadVisualReview.providerWrites: false` | Application-scoped settings; repository/workspace settings are ignored. Users controlling their own application settings can change them; enforce OS/network policy separately |
| Android | `disable_network: true`, `disable_provider_writes: true`, `secure_screen: true` | Managed application restrictions supplied by the organization's DPC/MDM; secure screen blocks app screenshots/recents previews through Android FLAG_SECURE |

A browser policy example is `{ "NetworkEnabled": false, "ProviderWritesEnabled": false }`; deploy it under the extension's actual installed ID using your browser's enterprise policy tooling. Configure Android restrictions for package `dev.kicadvizdiff.android`. No organization/device policy was installed or overridden by this source change.

Absent browser managed-storage APIs preserve ordinary behavior. A present API returning malformed, unreadable or unprovisioned policy fails closed for networking and provider writes. Such browsers may need an explicitly provisioned valid empty/allow policy even for normal connected use. Existing credentials do not override policy; sign-out and local viewing remain available. Already-sent network requests cannot be recalled. Controls govern the app's own workflows, not a malicious replacement client or privileged OS/browser extension.

For confidential projects, combine a reviewed patched package with denied external egress, an updated OS/browser/WebView, encrypted approved project storage and restricted clipboard/export/backup policy. Do not run the native KiCad CLI on untrusted designs outside a disposable nonprivileged VM/container with no secrets or network and bounded resources. The local browser viewer does not require native KiCad. The legacy native-render HTTP service is disabled unless `--allow-unsandboxed-native` is explicitly supplied, and then accepts loopback binding only; it is a trusted-development escape hatch, not a sandbox.

## Hosted public GitHub App

This is a deployment template for the public-repository GitHub App service; it does not install KiCad and has not been deployed or validated on a host. A public host still needs operational security review, maintained operating system and TLS updates, monitoring, backups, and incident response. Do not use it to serve private repository data.

1. Prepare a dedicated Linux x86-64 host. Review and build `Dockerfile.github-app`; the image uses a non-root UID, a read-only root filesystem through Compose, bounded CPU, memory, process count and temporary storage, and no Linux capabilities. The SQLite volume remains writable and needs appropriate disk quotas and protected backups. The default Docker image tag is mutable: pin a reviewed image digest and rebuild/update it under your own patch policy. The Python lock allows only the documented Linux x86-64 wheels for Python 3.11/3.12; no other architecture is claimed.
2. Create the GitHub App key and random webhook secret as separate host files outside the repository and web root. Set `GITHUB_PRIVATE_KEY_FILE` and `GITHUB_WEBHOOK_SECRET_FILE` to their absolute host paths in an appropriately restricted deployment environment file. Docker Compose local file secrets are bind mounts, not an encrypted secret manager; restrict host access and ensure UID 10001 can read each file. Set `VIZDIFF_PUBLIC_URL`, `GITHUB_APP_ID`, and `GITHUB_APP_INSTALL_URL` as documented in `docs/github-app.md`. Avoid placing either secret value in environment variables, logs, or the image.
3. Start a single instance with `docker compose --env-file /path/to/private.env -f compose.github-app.yml up --build -d`. The application port is published only on host loopback. Restrict access to the Docker socket and host loopback, and do not override the binding publicly. The host proxy must reach this loopback port. Verify the container health, secret readability and volume write permissions before routing traffic.
4. Install and review `deploy/nginx-github-app.conf` in nginx's `http` context. Replace the domain and certificate paths, use a trusted certificate, and validate with `nginx -t` before enabling it. The example applies connection and request rates by direct socket peer and strips client-provided forwarding identity headers; it does not trust forwarded IP addresses. If another proxy sits in front, the limit applies to that proxy as a whole. Configure firewall access to TLS and block direct access to the application.

The webhook location disables nginx request buffering so that its body streams to the application, whose absolute I/O deadline can bound the forwarded body. nginx body and upstream timeouts are inactivity limits; do not treat them as absolute deadlines. The nginx header timeout and edge admission behavior still require slow-client testing on the actual installation before exposure; this configuration has not been runtime-verified. The example rates and 1 MiB body limit are starting values; validate legitimate webhook sizes and tune them under load. Never treat rate limits as authentication.

Pin and review Actions, wheel hashes and npm lockfile updates; package checksums generated alongside assets protect transfer integrity but do not independently authenticate the build. A signed provenance workflow must accurately bind its builder identity and source commit to the release, including manual dispatch. A separate job attesting downloaded artifacts can misstate which job built them, so no attestation is claimed here. Design and validate this binding before relying on provenance. No real-host TLS, container, resource-limit, slow-client, or failover test was performed by this change.
